Lesson: Parse JSON
01 — What you'll learn

Parse JSON in Power Automate

Parse JSON turns a raw JSON string into typed dynamic content you can actually use. Without it, working with APIs is nearly impossible.

By the end of this lesson
  • Know what Parse JSON does and why it exists
  • Understand Content vs Schema
  • Generate a schema from a real sample
  • Access nested fields correctly
  • Handle arrays in JSON
  • Avoid the 6 most common mistakes
  • See 5 real-world use cases
💡 Goal: Turn any JSON response into clean, typed, usable fields — in one action.
02 — The problem

Why raw JSON is useless in Power Automate

When an HTTP call returns data, it looks like one giant string. You can't reference any part of it.

What the HTTP action gives you
{"id":1,"name":"Alice","email":"alice@example.com"}

Power Automate sees this as one string. No fields. No structure. Nothing to click.

⚠️ If you try to reference "name" directly, Power Automate doesn't know what you mean. You need to tell it the shape first.
03 — What Parse JSON does

A translator between raw text and typed fields

Parse JSON reads the raw JSON string, matches it against a schema, and exposes every field as dynamic content.

Before Parse JSON

{ "id": 1, "name": "Alice" }

After Parse JSON

Every field is now a chip you can drag into any action:

id name email

💡 Parse JSON doesn't change the data. It tells Power Automate the shape.
04 — Simple example

From blob to fields — step by step

// Raw response from an API { "id": 101, "name": "Shahabaj", "email": "shahabaj@example.com", "role": "Developer" }
After Parse JSON — 4 usable fields
  • id → 101
  • name → Shahabaj
  • email → shahabaj@example.com
  • role → Developer
💡 One action. Four fields. Reusable everywhere below.
05 — Why it matters

Without Parse JSON, your flow can't grow

  • You can't reference individual fields
  • You can't filter, loop, or transform the data
  • You can't send it to Excel, SharePoint, or Teams
  • You can't debug what's actually inside
  • You can't validate the response structure
💡 Parse JSON is the bridge between raw data and everything else.

07 — Schema basics

What is a JSON schema?

A schema describes the structure: which fields exist, their types, and which are required.

{ "type": "object", "properties": { "id": { "type": "integer" }, "name": { "type": "string" }, "active": { "type": "boolean" } } }
💡 You almost never write this by hand. Power Automate generates it.
08 — Generate from sample

The magic button that saves you hours

09 — Example 1: Simple object

Straightforward object → 4 fields

Sample JSON:

{ "id": 101, "name": "Shahabaj", "email": "s@example.com", "active": true }

Access a field:

// In any downstream action body('Parse_JSON')?['email']
💡 Top-level fields are one step: body('Parse_JSON')?['field'].
10 — Example 2: Nested object

When JSON contains objects inside objects

Sample JSON:

{ "id": 101, "user": { "name": "Shahabaj", "email": "s@example.com" }, "address": { "city": "Mumbai", "country": "India" } }

Access nested fields:

body('Parse_JSON')?['user']?['name'] body('Parse_JSON')?['address']?['city']
💡 Each nested level uses ?['key']. Chain them for depth.
11 — Example 3: Array of objects

When JSON returns a list

Sample JSON:

[ { "id": 1, "name": "Alice" }, { "id": 2, "name": "Bob" }, { "id": 3, "name": "Cara" } ]

The schema type is array with items of type object. Downstream:

// Use Apply to Each item()?['name']
💡 Arrays go through Apply to Each. Use item() for each element.
12 — Example 4: Mixed types

Strings, numbers, booleans, null

Real APIs mix types. Parse JSON handles them all.

{ "name": "Order #101", "amount": 249.99, "paid": true, "discount": null, "tags": ["urgent", "vip"] }
Watch out for null

If a field can be null, use coalesce(body('Parse_JSON')?['discount'], 0) to provide a fallback.

💡 Handle null explicitly or your flow will break.
13 — Example 5: API response (weather)

A real weather API response

{ "location": "Mumbai", "temperature": 32, "humidity": 78, "condition": "Sunny", "forecast": [ { "day": "Mon", "high": 34 }, { "day": "Tue", "high": 33 } ] }

After Parse JSON: location, temperature, humidity, condition, forecast are all chips.

💡 The forecast array is used with Apply to Each downstream.

Every way to reference parsed fields

27 — Pitfalls

Common mistakes (6 of them)

Tap each mistake to see why it trips beginners up.

1. Using dynamic content as the sample▼
When you click Generate from sample, paste a static JSON example. If you paste dynamic content, Power Automate can't read the schema and the generation fails.
2. Providing an incomplete sample▼
If your sample only has 2 fields but the real response has 5, only 2 will be available downstream. Always use a full, real response — including optional fields.
3. Wrong schema type (object vs array)▼
If the response is [{ ... }], the type is array. If it's { ... }, it's object. Getting this wrong breaks every downstream action.
4. Forgetting to handle empty responses▼
If the API returns nothing (empty string, null, or empty array), Parse JSON fails. Guard with a Condition: empty(body('HTTP')) before parsing.
5. Using outputs() instead of body()▼
Parse JSON outputs live in body('Parse_JSON') — not outputs(). That's the pattern. Mixing them up gives null values.
6. Not handling null fields▼
If a field can be null, wrap with coalesce(): coalesce(body('Parse_JSON')?['phone'], 'Not provided'). Otherwise, the flow may fail.
28 — Best practices

Write clean Parse JSON actions

  • Rename every action — Parse_Weather, not Parse_JSON
  • Generate the schema from a real, complete response
  • Store the sample in a comment or documentation
  • Test with empty or malformed responses
  • Use ?['key'] for optional fields
  • Validate the response before parsing when possible
💡 A named action is a gift to your future self.
