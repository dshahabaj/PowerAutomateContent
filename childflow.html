01 — The Hook

Your flow just hit 200 actions. Now what?

You've built it in one file. It works. But every change breaks something else. And you can't reuse any of it.

The reality of a monolithic flow
  • 200 actions in one canvas
  • Impossible to scroll — even in the designer
  • Debugging means tracing through everything
  • Copy-paste to reuse — code duplication everywhere
  • Team can't work on different parts
💡 In 25 minutes: You'll break this 200-action monster into one clean parent flow + 4 reusable child flows.
02 — The Problem

Monolithic flows are maintenance nightmares

The bigger your flow gets, the harder everything becomes. Not just for you — for anyone who inherits it.

The compounding problem

Every new feature adds more actions. Every change risks breaking something upstream. Every debugging session takes longer than the last.

⚠️ Monolithic flows don't scale. They can't be reused. They can't be tested. They can't be shared.

05 — What is a Child Flow

A flow called by another flow

A Child Flow is a separate flow that another flow triggers. It has its own inputs and outputs — like a function in programming.

The mental model

If a parent flow is a main function, a child flow is a helper function. It does one job, receives inputs, and returns outputs.

💡 Parent calls child. Child does its job. Parent receives the result. Done.
06 — Anatomy

The four parts of a Child Flow

👨‍👩‍👧 Parent Flow

Calls the child. Passes inputs. Receives outputs.

🧩 Child Flow

Has a special "manual trigger" with defined inputs.

📥 Inputs

Data the parent sends — strings, numbers, JSON, arrays.

📤 Outputs

Data the child sends back — "Respond to a PowerApp or flow" action.

07 — Comparison

Parent vs Child — when to use which

Parent Flow

The main orchestrator. Handles the trigger, decides what to do, calls children. Lives in the same solution as children.

Child Flow

A focused worker. Does one job. Reusable. Called by one or more parents.

💡 Rule: If the same logic is used twice — make it a child flow.

12 — Best practices

Designing a good child flow

  • One responsibility per child — don't mix concerns
  • Define all inputs clearly with descriptive names
  • Always end with a Response action
  • Handle errors inside the child (try/catch pattern)
  • Add it to the same Solution as the parent
  • Rename the trigger action — not just "Manually trigger a flow"

15 — Reference patterns

Accessing child flow outputs

// Basic output
body('Run_a_Child_Flow')?['greeting']

// Number output
body('Run_a_Child_Flow')?['count']

// Array output
body('Run_a_Child_Flow')?['items']

// Nested object
body('Run_a_Child_Flow')?['result']?['id']

// With null fallback
coalesce(body('Run_a_Child_Flow')?['greeting'], 'No greeting')
💡 Uses body() just like other actions. The name must match the child action's name.

21 — Compare

Child Flow vs Scope vs Duplicate

Child Flow

Reusable across flows. Deployable separately. Has its own run history.

Scope

Groups actions inside one flow. Not reusable elsewhere. Same run history.

Duplicate

Copy-paste logic in every flow. Maintenance nightmare. Never do this.

💡 Use Child Flow for reusability. Use Scope for grouping inside one flow.

39 — Error 1

Renamed child action breaks references

You rename the child action from "Run_a_Child_Flow" to "Run_Alert_Child". Every downstream reference breaks.

✕
Unable to find action
ActionNotFound · 400
The workflow expression references body('Run_a_Child_Flow') but no action with that name exists.
40 — Error 2

Wrong input type

Child expects a Number but the parent passes Text. The action fails on the first run.

✕
Invalid input type
InvalidParameter · 400
Parameter "Count" expects a number, received a string.
41 — Error 3

Missing response action

The child runs but never returns anything. The parent waits for a response — and times out.

✕
Child flow did not return a response
ActionTimedOut · 504
The child flow finished but did not call "Respond to a PowerApp or flow".
42 — Error 4

Circular reference

Parent calls child. Child calls parent. Infinite loop. Power Automate blocks it.

✕
Circular dependency detected
CircularReference · 400
Flow A calls Flow B, and Flow B calls Flow A. This creates an infinite loop.
43 — Error 5

Child in different solution

Parent and child must live in the same Solution. Otherwise the parent can't find the child.

✕
Child flow not found
FlowNotFound · 404
The child flow "Send-Error-Alert" is not in the current Solution.
44 — Error 6

Connection owner missing

Child flow uses a connection that the parent's service account doesn't have. Fails at runtime.

✕
Connection not authorized
ConnectionAuthorizationFailed
The connection 'shared_sharepointonline' is not available in this environment.

48 — Best practices

Rules for clean child flows

  • One responsibility per child flow
  • Rename every action — trigger, response, and child call
  • Always call "Respond to a PowerApp or flow"
  • Handle errors inside the child with Scope
  • Keep parent + child in the same Solution
  • Document the inputs and outputs on the child
  • Test the child standalone before using it in a parent
