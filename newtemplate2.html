04 — Why this matters

The problem with loops

Scenario

You have 500 SharePoint items. Only 12 are marked as "Approved". You need to email the assigned managers for those 12.

Without Filter Array

Apply to Each runs 500 times. You check each item inside the loop. Slow. Wasteful. Ugly.

With Filter Array

Filter first → 12 items. Apply to Each runs 12 times. 97% faster.

05 — What it is

From array + a condition

Filter Array needs two things: an array of items, and a rule that decides which ones stay.

Input

An array of items

Rule

A condition (e.g., amount greater than 100)

💡 Takeaway: The output is always an array. Use length() to count the matches.

09 — Deep dive: Output

What comes out

The output is always an array — even if only one item passes, or none at all.

// Get the filtered array body('Filter_array') // Count how many passed length(body('Filter_array')) // Get the first item (if you need a single one) first(body('Filter_array')) // Loop over the results Apply to each → body('Filter_array')
💡 Takeaway: Empty filter = empty array. Not an error. Design for it.

13 — Use case

Keep only active records

✅

The scenario

You've pulled 200 items from a SharePoint list. 180 of them are closed. You only need the 20 open ones.

item()?['status'] ne 'Closed'
Result

20 items. Loop runs 20 times instead of 200. 90% faster.

14 — Use case

Find items over a limit

💰

The scenario

You have a list of orders. You only want to alert the finance team about orders above $1,000.

item()?['amount'] gt 1000
Result

Only large orders trigger an alert. No spam to finance. Zero noise.

15 — Use case

Check if something exists

🔍

The scenario

You want to know if a user already exists in a list before creating a duplicate.

item()?['email'] eq 'user@company.com'
Then check

Use length(body('Filter_array')). If 0 → create. If 1+ → skip.

💡 Takeaway: Any time you say "only the ones where…", that's Filter Array.

17 — Advanced

Filtering nested items

Sometimes the array contains nested objects. Here's how to reach into them.

// Item structure { "id": 1, "title": "Order 1", "meta": { "priority": "high", "tags": ["urgent", "vip"] } } // Rule: filter where nested priority = 'high' item()?['meta']?['priority'] eq 'high' // Rule: filter where tags contains 'vip' contains(item()?['meta']?['tags'], 'vip')

18 — Learn from others

Common pitfalls

Tap a mistake to see why it trips beginners up.

Comparing text to a number▼
If Amount is stored as text, a "greater than 100" check can give odd results. Make sure the field is really a number first.
Text matches are case-sensitive▼
"Approved" and "approved" are not the same. Use toLower() on both sides before comparing.
Forgetting the output is always an array▼
Even if only one item matches, the output is still an array. Wrap it in first() if you need a single item.
Filtering after the loop instead of before▼
If you filter inside an Apply to Each, you still loop through every item. Always filter BEFORE the loop.
19 — Performance

4 ways to make flows faster

1. Filter before you loop

The most impactful change. Trim the array before Apply to Each.

2. Replace Condition inside loops

Instead of "If status = Approved" inside every iteration, pre-filter.

3. Use length() for existence checks

Don't loop to check if an item exists. Filter, then check length.

4. Pre-filter source arrays

If a "Get items" returns 500 rows, use OData filter at the source too.
