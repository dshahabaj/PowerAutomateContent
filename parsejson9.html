01 — The Hook

Your GitHub just sent this. Now what?

Every time someone merges a pull request, GitHub fires a webhook. It arrives in Power Automate as one giant string.

What lands in your flow
{"action":"closed","pull_request":{"merged":true,"user":{"login":"shahabaj"},"head":{"ref":"feature/login"}},"repository":{"name":"my-app","owner":{"login":"contoso"}}}
💡 In 25 minutes: You'll parse this, extract 4 fields, and post a Teams message — in one flow.
02 — The Problem

It looks fine. It works for nothing.

Power Automate treats the entire webhook body as a single string. You can see it. You just can't use any part of it.

You want to reference pull_request.user.login — but nothing appears

Try typing the field name in a downstream action. There are no chips. No autocomplete. No way to access it.

⚠️ Without Parse JSON, the webhook is a wall of text. Every downstream action is blocked.

05 — What is Parse JSON

A translator for raw JSON

Parse JSON reads a raw JSON string against a schema, and exposes every field as typed dynamic content.

Before

{"id":1,"name":"Alice"}

After

id name email

💡 Parse JSON doesn't change the data. It tells Power Automate the shape.
06 — Anatomy

The four parts of Parse JSON

📥 Content

The raw JSON string — usually body from the previous action.

🧬 Schema

The shape definition. Power Automate generates it from a sample.

📤 Outputs

Typed dynamic content chips — one per field.

🔗 Downstream

Access via body('Parse_JSON')?['key'].

07 — Schema

What a schema looks like

A schema declares which fields exist, their types, and which are required.

{
  "type": "object",
  "properties": {
    "id": { "type": "integer" },
    "name": { "type": "string" },
    "active": { "type": "boolean" }
  }
}
💡 You almost never write this by hand. Power Automate generates it.

21 — Compare

Parse JSON vs Compose

Parse JSON

Reads the shape. Interprets JSON structure. Needs a schema.

Compose

Holds a value. Static. Perfect for building JSON.

💡 Compose writes JSON. Parse JSON reads it.

Empty response guard

Wrap Parse JSON in a Condition to check the response isn't empty first.

Fix

42 — Edge case

Bot accounts in GitHub

Sometimes PRs are merged by bots. user.login becomes "github-actions[bot]".

Condition: not(endsWith(body('Parse_JSON')?['user']?['login'], '[bot]'))

48 — Best practices

Write clean Parse JSON actions

  • Rename every action — Parse_Weather not Parse_JSON
  • Generate the schema from a real, complete response
  • Store the sample in a comment or doc
  • Test with empty or malformed responses
  • Use ?['key'] for optional fields
  • Validate before parsing when possible
