02 — What it is

From array and a condition

Filter Array needs two things: an array of items, and a rule that decides which ones stay.

Input

Array of items

Rule

Condition (e.g., amount is greater than 100)

💡 Takeaway: The output is always an array. Use length() to count the matches.

05 — Where it shines

Four everyday use cases

✅ Keep only active records

Drop closed or archived items before doing anything else.

💰 Find items over a limit

Pick out orders above an amount, or tasks past a due date.

🔍 Check if something exists

Filter, then test whether the count is greater than zero.

⚡ Save loop runs

Trim the list first, so Apply to Each does less work.

💡 Takeaway: Any time you say "only the ones where…", that's Filter Array.

08 — Learn from others' mistakes

Common pitfalls

Tap a mistake to see why it trips beginners up.

Comparing text to a number ▼
If Amount is stored as text, a "greater than 100" check can give odd results. Make sure the field is really a number first.
Text matches are case-sensitive ▼
"Approved" and "approved" are not the same. Use toLower() on both sides before comparing.
Forgetting the output is always an array ▼
Even if only one item matches, the output is still an array. Wrap it in first() if you need a single item.
Filtering after the loop instead of before ▼
If you filter inside an Apply to Each, you still loop through every item. Always filter BEFORE the loop.
