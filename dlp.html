01

What is DLP?

Data Loss Prevention. A governance rule that prevents sensitive data from moving between blocked connectors.

If SharePoint is Business and Twitter is Non-Business — you cannot use both in the same flow. DLP blocks it.

02

Connector Classification

Business

Trusted connectors. SharePoint, Outlook, Teams, Dataverse.

Non-Business

External or risky. Twitter, Dropbox, personal Gmail.

Blocked Connectors that cannot be used at all in your tenant.
You cannot mix Business and Non-Business in the same flow. That's the rule.
03

How DLP Blocks Your Flow

Your flow works perfectly in Dev. Then it fails in Prod. No code change. Just a policy.

  • The flow uses a Business connector
  • It also uses a Non-Business connector
  • DLP policy blocks the combination
  • Flow fails before the first action runs
This is not a bug. This is governance working exactly as designed.
04

Where to Check DLP Policies

Power Platform Admin Center
  1. Go to admin.powerplatform.microsoft.com
  2. Click Policies → Data policies
  3. Review connector classifications
  4. Check environment-level policies
  5. Check tenant-level policies
If you're not an admin, ask yours. Only admins can see and change DLP policies.
05

The Fix

  • Whitelist the connector with your admin
  • Move the connector to Business classification
  • Split the flow into two separate flows
  • Use HTTP with Azure AD as a workaround
  • Move to a different environment with less strict DLP
You cannot fix DLP in the flow itself. It's an admin-level decision.
06

Common Mistakes

  • Building flows without checking DLP first
  • Using personal connectors for production flows
  • Assuming DLP is the same across all environments
  • Not documenting which connectors are blocked
  • Ignoring DLP warnings during flow creation
Test your DLP policies in Dev before you build anything for production.
07

Best Practices

  • Review DLP policies before every project
  • Keep a list of approved connectors
  • Use environment groups for policy inheritance
  • Align DLP with your security team
  • Log and monitor DLP blocks
DLP is not a blocker. It's a guardrail. Work with it, not against it.
