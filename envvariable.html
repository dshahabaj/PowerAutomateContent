01

What are Environment Variables?

Environment Variables are values that change from one environment to another — stored outside the flow itself.

Flow
Variable
Value
Same flow. Different values. Zero editing.
02

Why Hardcoding Breaks

Dev Environment SharePoint URL: contoso-dev.sharepoint.com
Production Environment SharePoint URL: contoso.sharepoint.com
If your flow hardcodes the Dev URL, it fails in Prod. Every single time.
03

Types of Environment Variables

Text

URLs, emails, IDs, names.

Number

Limits, thresholds, counts.

Boolean

True/False flags.

JSON

Structured config data.

Also: Secret (Azure Key Vault) and Data Source (for Dataverse connections).
04

How to Set Them Up

Inside a Solution
  1. Open your Solution
  2. Click New → More → Environment Variable
  3. Choose type (Text, Number, etc.)
  4. Set default value
  5. Use in flows via dynamic content
Once in the solution, values can be changed per environment during import.
05

Best Practices

  • Always use Environment Variables inside Solutions
  • Never hardcode URLs, IDs, or emails
  • Use descriptive names like SiteURL_Prod
  • Group related variables logically
  • Document every variable's purpose
If a value changes per environment, it belongs in an Environment Variable.
06

Common Mistakes

  • Hardcoding URLs inside flows
  • Using Environment Variables outside Solutions
  • Sharing a variable across flows without documentation
  • Forgetting to update variable values during import
