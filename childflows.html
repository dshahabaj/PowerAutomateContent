01

What is a Child Flow?

A Child Flow is a separate flow that another flow calls — like a function in programming.

Parent Flow
Child Flow
Instead of one massive flow, you build small, focused pieces that work together.
02

Why Modularity Matters

  • Reuse the same logic in multiple flows
  • Easier to debug — smaller pieces
  • Easier to update — change one child flow
  • Better performance and clarity
  • Teams can work on different pieces
One giant flow is a maintenance nightmare. Modular flows are maintainable.
03

Passing Data In and Out

Inputs Data the parent sends to the child (IDs, strings, JSON).
Outputs Data the child sends back to the parent.
Define your inputs and outputs first. Then build the logic around them.
04

Real-World Architecture

Error Handling Child Flow Every flow calls one shared child flow for error alerts. Change the format once. Update everywhere.
Approval Child Flow Reusable approval logic called from multiple parent flows.
Design your child flows around a single responsibility.
05

When to Use Child Flows

  • Same logic used in 2+ flows
  • Your flow has 50+ actions
  • You want a clean, readable design
  • Different teams own different pieces
  • You need centralized error handling
If you're copy-pasting logic between flows, it's time for a child flow.
06

Common Mistakes

  • Passing too much data into a child flow
  • Making child flows too generic
  • Not documenting inputs and outputs
  • Forgetting to add the child flow to the Solution
07
