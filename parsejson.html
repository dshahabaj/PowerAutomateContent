Lesson: Parse JSON
01 — What you'll learn

Parse JSON in Power Automate

Parse JSON turns a raw JSON string into typed dynamic content you can actually use. Without it, working with APIs is painful.

By the end

You'll know what Parse JSON does, how the schema generation works, how to handle nested data, and how to fix the errors most beginners hit.

💡 Goal: Turn any JSON response into usable dynamic fields — in one action.
02 — What it is

A translator for raw JSON

When an HTTP action or custom connector returns data, it comes back as a raw JSON string. You can't reference individual fields from a string.

Before Parse JSON

A big blob of text — { "id": 1, "name": "Alice" }

After Parse JSON

Every field is now a dynamic content chip — id name

💡 Parse JSON doesn't change the data. It tells Power Automate the shape.
03 — Simple example

From raw text to fields

{
  "id": 1,
  "name": "Alice",
  "email": "alice@example.com"
}

After Parse JSON, you can drag id, name, and email into any downstream action.

💡 One action unlocks every field in the response.
04 — Why it matters

APIs without Parse JSON are unusable

  • You can't reference individual fields
  • You can't filter, loop, or transform the data
  • You can't send it to Excel, SharePoint, or Teams
  • You can't debug what's actually inside
💡 Parse JSON is the bridge between raw data and usable data.

06 — Schema basics

What is a JSON schema?

A schema describes the structure of your JSON: which fields exist, what type each one is, and whether they're required.

{
  "type": "object",
  "properties": {
    "id": { "type": "integer" },
    "name": { "type": "string" }
  }
}
💡 You don't write the schema by hand. Power Automate generates it.

09 — Nested JSON

When objects have objects

Real APIs return nested structures. Parse JSON handles them — you just need the right sample.

{
  "user": { "name": "Alice" },
  "address": { "city": "Mumbai" }
}

Downstream, access with body('Parse_JSON')?['user']?['name'].

💡 Nested objects use the ?['key'] pattern repeatedly.
10 — Arrays in JSON

When JSON has a list

If the response is an array of objects, the schema type is array and the top-level field is body.

💡 Arrays go through Apply to Each. Objects go through direct field access.

20 — Pitfalls

Common mistakes

Tap a mistake to see why it trips beginners up.

Using dynamic content as the sample▼
When you click Generate from sample, paste a static JSON example. If you paste dynamic content, the schema won't be built.
Providing an incomplete sample▼
If your sample only has 2 fields but the real response has 5, only 2 will be available downstream. Always use a full, real response.
Wrong schema type (object vs array)▼
If the response is [{ ... }], the type is array. If it's { ... }, it's object. The wrong type breaks downstream.
Forgetting to handle empty responses▼
If the API returns nothing, Parse JSON fails. Check for empty content first using empty() or a Condition.
Using outputs() instead of body()▼
Parse JSON outputs live in body('Parse_JSON') — not outputs(). That's the pattern.
21 — Best practices

Write clean Parse JSON actions

  • Always rename the action — Parse_Weather, not Parse_JSON
  • Generate the schema from a real, complete response
  • Store the sample in a comment or documentation
  • Test with empty or malformed responses
  • Use ?['key'] for optional fields
💡 Named actions = easier flows to debug later.
22 — Advanced

Handle optional fields

Some APIs return fields only when present. Use coalesce() to provide a fallback value.

Example

coalesce(body('Parse_JSON')?['phone'], 'Not provided')

💡 Guard against missing fields before your flow breaks.
23 — Performance

Why it's fast

Parse JSON is a single-pass operation. It reads the schema once and exposes all fields at once.

💡 No looping required to read the structure.
